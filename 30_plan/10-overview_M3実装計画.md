# M3 実装計画

前提: [spec-40-data_M3コンテンツモデルと互換性](../40_spec/40-data_M3コンテンツモデルと互換性.md), [memo-0001-10-overview_M2引き継ぎ申し送り](../10_memo/0001-10-overview_M2引き継ぎ申し送り.md)

`concepts.json` の項目定義、永久IDの採番規則、localStorage 移行の詳細は前者にある。
**この計画は「何を・どの順で・どこまでやれば終わりか」だけを持つ。**

## 目的

M2 の「短い解説」を、**4選択肢すべてを同じ密度で説明する用語辞書ベースの解説**へ置き換える。
同時に、問題の追加・改善で ★ と誤答履歴が壊れない永久ID体系へ移行し、数百〜1,200問への拡張余地を作る。

## 完了条件

- [ ] 回答後、A〜D すべてについて「用語 / 英語正式名称 / 日本語 / 意味 / 試験ポイント / この設問で適切・不適切な理由 / 関連語」が表示される
- [ ] 同じ用語の説明が複数の設問へ複製されていない（`concepts.json` を直せば全設問に反映される）
- [ ] 既存の localStorage（`itss-l5-study-state-v2`）から ★・誤答数・習得Lv・復習予定が欠損なく v3 へ移行される
- [ ] `itss-l5-study-state-v2` / `v1` が削除されずに残っている（ロールバック可能）
- [ ] 新規ユーザー（localStorage 空）でも初回起動が成功する

## 手順

順序は「軽くて後続の分岐を決めるもの」を先に置く。

- [ ] 1. 移行前の退避を作る（🔥 破壊的変更の前に置く）
  - [ ] 現行アプリの JSON エクスポート機能で学習履歴を書き出し、手元に保存（👤）
  - [ ] `docs/data/questions.json` の 81問の ID 一覧を控える
- [ ] 2. `tools/` に永久IDマッピング生成スクリプトを追加し、`legacy-id-map.json` を作る
  - 旧ID（`str-tm-01` 等）81件 → `security.oauth2.term_to_meaning.001` 形式
  - ⚠️ 並べ替えて旧IDを再生成しないこと。既存履歴の参照キーが切れる
- [ ] 3. `docs/data/concepts.json`（36概念の辞書）を作る
  - まず既存 `explanation` / `choice_notes` / `related_terms` から機械的に初期値を起こし、その後に品質を上げる
- [ ] 4. `docs/data/questions-v3.json` を生成する（設問固有情報のみ。説明は `concept_id` 参照）
- [ ] 5. `app.js` に v2/v1 → v3 マイグレーションを実装する
- [ ] 6. `app.js` の解説レンダリングを concepts 参照方式へ変更する
- [ ] 7. `styles.css` に4選択肢の詳細カードUIを追加する
- [ ] 8. `sw.js` の `CACHE` を `itss-l5-v4` へ上げ、新JSONを `ASSETS` に追加する
- [ ] 9. 検証
  - [ ] 旧 localStorage を仕込んだ状態でマイグレーションを実行し、★・誤答数・習得Lvの件数が一致することを確認
  - [ ] localStorage 空の新規状態で起動を確認
  - [ ] GitHub Pages 上でスマホ実機確認（👤）
- [ ] 10. 36概念の説明品質をレビューし、試験ポイントを実務語ではなく出題語で書き直す
- [ ] 11. 概念と問題を増やす（M3 完了後に `30_plan/` へ別途計画を起こす。この計画には含めない）

## この計画で決めていないこと

- **問題の仕入れ方針**: IPA公開シラバス・試験要綱から概念を抽出し、過去問の**論点**を正規化して ORIGINAL 問題を作る方針まで決まっている。過去問本文の複製はしない。具体的な収集手順は M3 完了後に `50_workflow` へ起こす。
- **Supabase 同期**: 保留。解除条件は「PCとスマホの2端末で同一の学習履歴を使いたくなったとき」（→ [CLAUDE.md](../CLAUDE.md)）。
