# IPA過去問の取り込み

前提: [spec-40-data_M3コンテンツモデル](../40_spec/40-data_M3コンテンツモデルと互換性.md)

検証ステータス: 2026-08-19 に5試験区分×直近2年（12回・300問）で通して確認済み
（Python 3.13.7 / PyMuPDF / Node 24.8.0 / Playwright 1.62.1）。

## この手順は何をするか

IPA が公開している科目A-2（旧・午前II）の過去問PDFを取り込み、
アプリが読む `docs/data/questions-v3.json` へ**出典つきで**追加する。

```
IPAのPDF ──fetch_exams.py──▶ 60_exams/（PDFとページPNG。追跡外）
                                  │
                     転記（人・AI）│  解答例の読み取り（別経路）
                                  ▼
              extract-*.json  +  answer-key.json
                                  │
                       merge_exam.py（構造と正解の突合）
                                  ▼
                            merged.json
                                  │
                     normalize_exams.py（改変判定 ＋ Git管理下へ書き出し）
                                  ▼
                        content/exams/<試験>_<年度>.json
                                  │            ＋ content/past-concepts.json（主題の用語）
                                  │            ＋ content/past-reasons.json（選択肢ごとの解説）
                                  │            ＋ docs/data/concepts.json（用語辞書）
                       build_content.py（出典と用語を付けて配信データへ）
                                  ▼
                       docs/data/questions-v3.json
```

## 語彙（コマンド引数とIDに出る値）

**試験区分コード**（`merge_exam.py` の第1引数、ファイル名の接頭辞、設問IDに出る）:

| コード | 試験 | この手順で付く領域（`domain`） |
|--------|------|------------------------------|
| `ST` | ITストラテジスト試験 | `STRATEGY` |
| `SA` | システムアーキテクト試験 | `ARCHITECTURE` |
| `SC` | 情報処理安全確保支援士試験 | `SECURITY` |
| `PM` | プロジェクトマネージャ試験 | `PM` |
| `AU` | システム監査技術者試験 | `AUDIT` |

**年度キー**は `<西暦4桁>r<令和2桁><期>`。期は `h`＝春期、`a`＝秋期。
例: `2025r07h` ＝ 令和7年度 春期、`2024r06a` ＝ 令和6年度 秋期。
⚠️ 西暦は**年度**であり、秋期の実施月が翌年になる場合も年度側を書く。

**設問ID**は `past.<試験区分コードの小文字>.<年度キー>.q<問番号2桁>`。
例: `past.pm.2024r06a.q08` ＝ 令和6年度 秋期 プロジェクトマネージャ試験 問8。
このIDは 055・057 の対応表のキーになり、学習履歴の参照キーにもなる。
🔥 **一度配信したIDは変えない。** 変えるとその問の履歴が切れる。

## 🔥 利用条件（外すと過去問を使えなくなる）

IPA は公表済みの過去問題について許諾も使用料も不要としているが、次の3点が条件である。

1. **出典を明記する**（年度・期・試験区分・時間区分・問番号）
2. **改変した場合はその旨も明記する**
3. 著作権はIPAが放棄していない

この手順では、1 を `source_refs`、2 を `modification_label` として持たせ、
`docs/js/source.js` が出題画面へ表示する。改変まわりは3段階で名前が変わる。

| 欄 | 誰が書くか | 中身 |
|----|-----------|------|
| `modified` / `modification_note` | 030 で転記者が書く | 改変したという申告と、その内容 |
| `modification_kind` | 050 が機械的に決める | `figure_to_text` / `notation` / `layout_only` など分類値 |
| `modification_label` | 060 が分類から付ける | 画面に出す文言 |

⚠️ **画面に出るかどうかを決めるのは `modification_kind`** であって転記者の `modified` ではない。
**データにフィールドがあるだけでは条件を満たさない。
画面に出て初めて満たされる。** 表示が壊れてもアプリは動くので、`node tools/test_past.mjs` で機械的に見る。

⚠️ 出典の時間区分は**当時の名称（午前II）のまま**書く。2026年度からの「科目A-2」へ読み替えない。
出典は原本を特定するための表記であり、読み替えると原本を指せなくなる。

## 手順

コマンドはすべて**リポジトリのルート**で実行する。相対パスがそこを基準に書かれている。

### 010. 取得と画像化

```bash
python tools/fetch_exams.py --list     # 対象の一覧を見る
python tools/fetch_exams.py --all      # TARGETS を一括取得
```

- 出力は `60_exams/<試験>/<年度>/`（`.gitignore` 対象。PDFは1本2MB程度）
- 新しい年度を足すときは `YEARS` へURLのハッシュ部分を、`TARGETS` へ実施された組合せを追記する
- ⚠️ **PDFは全ページ画像でテキスト層が無い。** 文字を機械抽出できないので、読み取りは150dpiのPNGに対して行う

### 020. 解答例を先に、別経路で読む

`60_exams/<試験>/<年度>/answer-key.json` を作る。形式:

```json
{ "source": "令和7年度 春期 ITストラテジスト試験 午前II 解答例",
  "answers": { "1": "ウ", "2": "ア", "...": "..." } }
```

🔥 **正解は解答例PDFから、問題文の転記とは別の経路で読み取る。**
転記と同じ経路で正解を得ると、突合が自己参照になって検算の意味が消える。

### 030. 問題文を転記する

`60_exams/<試験>/<年度>/extract-*.json` を作る。1ファイルに何問入れてもよい（分担のため複数可）。
1問の形式:

```json
{ "question_no": 5, "page": 5, "stem": "...", "choices": ["...", "...", "...", "..."],
  "has_figure": true, "figure_text": "図を文にしたもの",
  "modified": true, "modification_note": "何を変えたか", "note": "不確かな点" }
```

- 選択肢の記号（ア・イ・ウ・エ）は `choices` に**含めない**
- 上付きは `^{...}`、下付きは `_{...}` で保つ。⚠️ 平文化すると式が意味を失う（`5.2L^{0.98}` → `5.2L0.98`）
- **図・表・グラフがある問は `figure_text` に文で書く。** 問題文が「図のとおり」と書いている設問は、
  これが無いと解けない
- `note` は「自信が無い」の申告欄。ここに書かれた問は 040 で一覧に出るので、画像と読み合わせる

⚠️ AIへ分担させる場合は、**そのエージェント自身に読み取らせる**こと。実測で、指示を再委譲しようとして
1件も作業せずに戻ったエージェントがあった。「あなた自身が画像を開いて読み取り、結果を書き出す。
この作業を他のエージェントへ委譲してはいけない」と明示する。

### 040. 突合して検算する

```bash
python tools/merge_exam.py ST 2025r07h
```

`extract-*.json` を結合し、`answer-key.json` と突合して `merged.json` を作る。
終了コード 1 なら取り込まない。検出するもの:

- 問番号の欠落・重複、選択肢が4個でない、問題文や選択肢が空
- 選択肢の先頭に記号が残っている（「ア　ABC分析」のような転記ミス）
- 改変ありと申告しているのに `modification_note` が空
- 解答例に無い問番号

⚠️ **ここで検算できるのは構造と正解記号だけで、問題文が原文どおりかは検算できない。**
本文の正しさは画像との読み合わせで担保する。

### 050. 改変判定を当て、Git管理下へ書き出す

```bash
python tools/normalize_exams.py
```

12回分の転記は担当を分けたため、同じ性質のものが片方は改変・片方は注記とばらついていた。
このスクリプトが基準を1か所に集約し、全問へ当て直して `content/exams/` へ書き出す。

- 🔥 **`figure_text` があれば、分類表に無くても改変（`figure_to_text`）とみなす。**
  実測で、転記者が `modified` を立てずに図を文章化した問が **25問** あった。
  「フラグが立った問だけを分類する」設計では、その25問の改変が漏れていた
- 🔥 **`60_exams/` は追跡外なので、この書き出しが無いと分類の変更がGitに残らない**
- 分類表（`CLASSIFY`）に無い問で注記や改変フラグがあると終了コード 1 になる。新しい回を足したら追記する

### 055. 主題の用語を決め、辞書へ足す

過去問1問につき、その問が問うている用語を1つ決めて `content/past-concepts.json` へ登録する。
対象の設問IDは、050 の出力から機械的に出せる（配信データはまだ無いので、そちらは参照できない）。

```bash
python - <<'EOF'
import json, io
exam, year = 'PM', '2025r07a'
doc = json.load(io.open(f'content/exams/{exam}_{year}.json', encoding='utf-8'))
for q in doc['questions']:
    print(f"past.{exam.lower()}.{year}.q{q['question_no']:02}")
EOF
```


```json
{ "map": { "past.pm.2024r06a.q08": "pm.evm", "...": "..." } }
```

- 用語が `docs/data/concepts.json` に無ければ足す。1件の形は既存の項目に合わせる
  （`id` / `domain` / `term` / `full_name` / `japanese` / `meaning` / `exam_tip` / `related` / `related_terms`）
- `domain` は**出題された試験区分ではなく用語の分野**で決める。監査の回に出た暗号の用語は SECURITY にする。
  そうしないと、辞書を領域で絞ったときに用語が見つからない
- `choice_definition` は自作問の選択肢文と突き合わせるための欄なので、過去問用の語には不要
- 🔥 **対応表に無い過去問があると `npm run build` が止まる。** 主題の用語が無い問は、
  解説にも用語辞書にも現れない「解いても何も残らない問」になるため、黙って通さない

⚠️ **AIに書かせた説明は一次情報で裏取りするまで暫定として扱う。**
規格の条文番号、年号、数値、機能の個数（NIST CSF 2.0 の6機能など）は取り違えやすい。

### 057. 選択肢ごとの解説を書く

055 とは独立しているので、順序を入れ替えても、片方だけ先に進めてもよい。
参照するのは 050 の出力（設問と選択肢）だけで、主題の用語は使わない。

選択肢1つにつき1〜2文で「なぜ正しいか／なぜ違うか」を書き、
`content/past-reasons.json` へ設問IDごとに**4件**登録する。

```json
{ "map": { "past.pm.2024r06a.q25": ["採用時の適格性検査は…", "…", "…", "…"] } }
```

- 並びは選択肢**ア・イ・ウ・エの順**（画面ではA〜Dとして出る）
- 誤答は「違う」で終わらせず、**その選択肢が何の説明なのか**を書く。
  「これはSWOT分析の説明」まで書けば、誤答選択肢自体が1つの学習項目になる
- 正解には「正解。」と書かない。画面に正解バッジが出るので二重になる
- 計算問題は、正しい式と値に加えて**各誤答がどの取り違えで出る値か**を書く。
  これが無いと、自分がどこで間違えたのかが分からない
- 🔥 **4件そろっていない、または空文字が混ざっていると `npm run build` が `ValueError` で止まる。**
  1つだけ空欄の状態は画面上「解説が壊れている」ように見えるため、黙って通さない
- 未執筆の問があってもビルドは通る（未執筆の問数を警告として出す）。
  **未執筆が0問**になっていることは `npm test`（`tools/test_past.mjs`）が検査する

### 060. 配信データを生成して確かめる

```bash
npm run build      # = python tools/build_content.py
npm test           # 履歴移行 + 用語辞書 + 過去問（出典・改変・記法・解説の網羅）
npm run shoot -- past
```

`build_content.py` は出典の無い過去問があると `ValueError` で止まる。
`test_past.mjs` は PM領域の過去問を**全問**画面へ出し、出典が出た数を数える。
⚠️ 1問だけ見て通すと「たまたま出典のある問が当たった」と区別できない。

## 増やすとき

1. `tools/fetch_exams.py` の `YEARS` へ年度ページのハッシュ、`TARGETS` へ実施された組合せを追記
2. 010〜060 をその回について実行
3. 新しい試験区分を足すなら、次の4か所を揃える（1か所でも漏れると、データはあるのに選べない状態になる）
   - `tools/build_content.py` の `EXAM_DOMAIN` / `EXAM_NAME`
   - `docs/js/app.js` の `DOMAINS` / `DOMAIN_LABEL`
   - `docs/js/glossary.js` の `DOMAIN_LABEL` / `DOMAIN_ORDER`
   - `docs/index.html` の `domainSelect` と `glossaryDomain`
4. `docs/sw.js` の `CACHE` 名は、`docs/` 配下の**ファイル配置**を変えたときだけ上げる
   （データの中身だけが変わる場合は、fetch優先の実装なので上げなくてよい）

## 解説を書く場所（用語カードと選択肢の解説）

過去問の回答後には2種類のカードが出る。**同じ内容を両方へ書かない。**
書く場所を取り違えると、用語の説明が設問の数だけ複製される。

- **「この設問の主題」カード**（1枚）— `concept_id` から `concepts.json` を引いて出す。
  用語そのものの説明（意味・試験ポイント・関連語）はここにしか置かない
- **選択肢A〜Dのカード**（4枚）— `past-reasons.json` の文をそのまま出す。
  ここには**この設問での適否の理由だけ**を書く

自作問では選択肢が用語なので辞書から自動生成できるが、
過去問の選択肢は文章なので突き合わせる相手がない。だから手で書く。
