# ADR-0004 出題の選び方と、習得指標の扱い

- 日付: 2026-08-20
- 状態: 採用（実装・測定済み 2026-08-20）
- 前提: [spec-40-data_M3コンテンツモデル](../40_spec/40-data_M3コンテンツモデルと互換性.md) /
  [memo-0002-30-app_UI印象とゲーミフィケーション](../10_memo/0002-30-app_UI印象とゲーミフィケーションの検討.md)

## この文書で使う語

- **習得Lv**: 問題ごとの到達段階。Lv1 = 答えた／Lv2 = 正解した／Lv3 = 別の日に2連続で正解した／
  Lv4 = Lv3以上を**7日以上空けて**正解した（＝画面の「習得」）。判定は `docs/js/app.js` の `masteryAfterAt()`。
- **間隔表**: 次に出す日を決める日数。`docs/js/app.js` の `reviewInterval()` にあり、
  不正解なら1日後、正解なら習得Lvに応じて 1・2・4・9・21日後（`next_review_at` に入る）。
- **復習期限が来ている**: `next_review_at` が現在時刻を過ぎている状態（`isDue()`）。
- **★重点**: 利用者が出題画面の☆を押して付ける印。復習リストに集まる。
- **KPI**: ダッシュボード上部に並ぶ4つの数字（習得（Lv4）／30日回答／30日正答率／誤答→習得）。
- **`みっちりやる`**: ホームにある、問題数・領域・対象・形式を指定して出題する枠。
- **重複**: あるセッションのn問のうち、それ以前のセッションで既に出た設問の数（の割合）。
- **抽選**: 重みに比例した確率で1件引くこと（`drawIndex()`）。

## ✅ 結論

🔥 **間隔反復の芯（習得Lvの判定と間隔表）は触らない。** 直すのは「出題の選び方」と「見せ方」だけ。

1. **出題の重み** = 基礎点 × `0.5^(直近7日にその問題を出した回数)`
   - 基礎点: 復習期限到来 +80（超過日数を最大 +20）／★重点 +25／未回答 +20／
     **直前の回答が誤答** +25／`(4 − 習得Lv) × 5`
   - 出すたびに半減し、7日より古い出題記録は捨てるので**放っておけば重みが戻る**
2. **選び方**: n問のうち `⌈n/3⌉` を重みの高い順、残りは候補から**抽選**。
   **当日すでに出した問題は乱択の対象外**。「今日の3問」= スコア1問 + ランダム2問
3. **`last_wrong_at` による永久 +45 を廃止**し、「直前の回答が誤答か」に置き換える
4. **習得指標は表示だけ直す**。ダッシュボードの領域別を **Lv1〜4の積み上げ**（「領域別 到達状況」）にし、
   KPIを「習得（Lv4）」と表記して条件を1行添える

5. **出題した記録**は `state.progress[問題ID].served_at`（ISO文字列の配列。7日より古いものは
   書き込み時に捨てる）に持つ。⚠️ Supabase同期で他端末の記録から作り直すと**この配列は消える**
   （回答ログ `state.attempts` から復元できないため）。散らし方が一度リセットされるだけなので許容する。

受け入れ基準と実測（2026-08-20、`npm run measure`＝`node tools/measure_pick.mjs`。
初回のみ `npm install` と `npx playwright install chromium` が必要）:

- [x] 誤答運用で20問×4本を回したとき、4本目の既出重複 100% → **0%**（基準は10%以下）
- [x] 80問回して出る設問の実数 28問 → **80問**（のべ80問がすべて別の設問。基準は70問以上）
- [x] 正答運用でも 2〜4本目の重複 0〜5%（改修前は 0 / 15 / 20%）

⚠️ 測定は空の localStorage から始めるので、実機の履歴とは条件が違う。値は前後比較の指標として読む。
⚠️ 乱数は差し替えていないため、実行ごとに数%動く。桁で読む。

## 却下した選択肢

- **誤答の加点を日数で減衰させる（当日〜3日は満点、以後細り、30日超で0）**
  - 当日の重複は減るが、**2日目以降の最初のセッションでは同じ集団が先頭に戻る**。
    1〜3日のうちに細切れで何度も回す使い方（このアプリの想定）では効かない。
- **点数そのものを永続させ、出題時に x0.5 して書き戻す**
  - 発想（出したという事実を冷却に使う）は採用したが、そのままでは**回復手段が無い**。
    10回出た問題は 0.5¹⁰ ≒ 0.001 で二度と出なくなる。
    → 点を持たず「**直近7日の出題回数**」だけを持ち、7日で自然に戻る形にした。
- **復習期限を唯一の門にする（期限前の問題は出さない）**
  - 間隔反復として最も正しく、当日の重複も構造的に消えるが、
    1日の学習量が間隔表（1・2・4・9・21日）だけで決まる。
    「今日はもう少しやる」に応えられず、`みっちりやる` の存在意義が薄れる。
- **当日の出題キューを日単位で確定して消費する**
  - 「今日の残り12問」が出せて見通しは良いが、状態を1つ増やし実装量が倍。
    ⚠️ **重みの冷却（結論1）を入れた上で、後から足せる**。
- **期限以外のスコアを全部捨てる（期限＋未回答のみ）**
  - 仕様は2行で説明できるが、★を付けた問題が自動出題に出てこなくなり、★の意味が痩せる。
- **習得（Lv4）の「7日以上空けて正解」条件を外す**
  - 数字はすぐ動くが、間隔反復の定義が変わり、**過去の履歴の意味まで変わる**。
- **習得率の表示はそのままで、注記だけ足す**
  - 最初の1週間ずっと 0/381 のままで、毎日やっても動かない画面が残る。

## 経緯・根拠

「テストするたび同じ問題が偏って出る」という指摘を、実アプリを操作して測った。
測り方は `tools/measure_pick.mjs`（Playwright で「条件指定でスタート」から20問のセッションを
同じ日に4本回し、出た問題文を突き合わせる）。既定は毎問「ア」を押すので誤答が混ざり、
`CORRECT=1` を付けると設問データから正解の位置を引いて毎問正答する。
🔥 乱数は差し替えない（撮影スクリプトとは逆）。本物の `Math.random()` で測る。

| 回答のしかた | 2本目 | 3本目 | 4本目 | 80問で出た実数 |
|---|---|---|---|---|
| 毎問わざと誤答 | 65% | 95% | **100%** | **28問** / 381 |
| 毎問正答 | 0% | 15% | 20% | 73問 / 381 |

偏るのは**一度でも誤答した問題**だった。原因は2つ。

1. `last_wrong_at` は一度誤答すると**永久に残る**（`docs/js/app.js` の
   `last_wrong_at: correct ? p.last_wrong_at : now` — 正解しても消していない）。
   その `+45` が減衰しないため、10年前の誤答も今日の誤答も同じ重みで上位に居座る。
   🔥 誤答は `next_review_at` を1日後に詰めることで**既に**処理されており、加点は**二重計上**だった。
2. 上位から**決定的に** n 件取るうえ、ゆらぎが `Math.random() * 10` しかないので、
   +45 を持つ集団の中の順位まで毎回ほぼ同じになる。

習得指標（Lv4）が0%のままだったのは仕様どおりで、バグではない
（Lv3=別の日に2連続正解 → Lv4=それを7日以上空けて正解。初回セッションでは
`correct_streak` が 0→1 にしかならないので必ず Lv2 で止まる）。
⚠️ **正しい定義でも、画面上は「毎日やっても動かない棒」＝故障と区別できない。**
判定ロジックではなく表示を直す、という切り分けをここで確定した。

誤答の追跡を自動出題から外せる理由は、**復習リスト**（誤答・★・期限到来を集めた画面、
1問ずつ「解く」ボタン付き）と「対象＝誤答歴あり」フィルタが既にあるため。
執拗に追うのは自動出題の役目ではない。

## 実装（2026-08-20）

- `docs/js/app.js`: `scoreQuestion()` を廃止し `questionWeight()` / `drawIndex()` / `pickQuestions()` /
  `recordServe()` / `serveCount()` / `servedToday()` を新設。`chooseDaily()` は `pickQuestions(questions, 3)` の1行に、
  「条件指定でスタート」は `pickQuestions(filteredQuestions(), n)` になった
- `filteredQuestions()` は**並べ替えをやめた**（並べて上位から取るのが偏りの片方の原因だったため）
- 出題の記録は `renderQuestion()` で行う。⚠️ 選んだ時点ではなく**画面に出した時点**
  （途中でやめたセッションの未表示分に冷却をかけないため）
- 復習リストの並びを決定的にした（期限到来 → 誤答の多い順 → Lvの低い順）。
  以前は出題スコアで並べており、乱数のゆらぎで**再描画のたびに順番が変わっていた**
- 検査: `tools/test_ui.mjs` に「同じ日に続けて回しても同じ設問が出直さない」（5問×2本）を追加。
  本格的な測定は `npm run measure`

## 覆る条件

- 実測で受け入れ基準を満たせなかったとき（とくに `⌈n/3⌉` のスコア枠が効きすぎる場合）は、
  スコア枠の比率を下げるか、却下した「当日の出題キュー」を足す。
- 復習が薄いと感じるようになったら、次に触るのは**間隔表**（`docs/js/app.js` の `reviewInterval()`）
  であって、出題の点付けではない。

## 副次的な決定（測定スクリプトを常設にする）

- 偏りの測定は使い捨てにせず `tools/measure_pick.mjs` として残し、`npm run measure` で引けるようにする。
  🔥 「同じ問題ばかり出る」は体感でしか気づけず、体感は次の変更で必ず忘れられる。数えられる形にしておく。
