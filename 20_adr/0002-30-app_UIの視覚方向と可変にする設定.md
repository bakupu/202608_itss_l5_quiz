# ADR-0002 UIの視覚方向と、利用者が変えられる設定

- 日付: 2026-08-20
- 状態: 採用
- 前提: [memo-0002-30-app_UI印象とゲーミフィケーション](../10_memo/0002-30-app_UI印象とゲーミフィケーションの検討.md)

## 結論

- 視覚方向は **「答案と朱入れ」**。題材（IPAの試験問題）そのものから引く。
  - 問題文と選択肢は **明朝**（本番PDFと同じ＝試験の紙）、ラベル・ボタン・ナビは **ゴシック**（アプリの声）。
    この書体の使い分けが「どこが試験問題で、どこがアプリか」の判別を担う。
  - 正誤は **朱の ○ / ×**。朱は採点マークと誤答だけに使い、面積を持たせない。
- **配色・問題文の書体・文字サイズを利用者が選べる**ようにする。
  選んだ値の保存先は **localStorage のキー `itss-l5-ui-v1`**（学習履歴のキー `itss-l5-study-state-v1/v2/v3` とは別）。
  - 配色: 答案（既定）／やわらか／夜／端末に合わせる
    （配色名「答案」は、この視覚方向をそのまま写した明るい配色1種の名前。方向の名前と同じ語を使っている）
  - 書体: 明朝（既定）／ゴシック、文字サイズ: 小・標準・大
- **書体はOS同梱のものだけ**を使う。外部フォント（Google Fonts 等）は使わない。
- 選択肢の記号は **ア〜エ**（IPA本番と同じ）。`1`〜`4` キーでも答えられる。
- 回答後の選択肢の解説は **既定で4つとも開く**。畳むのは設定の選択肢に留める。

## 却下した選択肢

- **夜の計器盤（暗い背景＋アクセント1色）を主方向にする**
  - 夜の学習に強くデータも締まって見えるが、「黒背景＋蛍光1色」は題材と何のつながりもなく、
    かつ現在もっとも生成物らしい配色である。→ **配色の選択肢「夜」として吸収**し、主方向にはしない。
- **現状（Inter＋灰背景＋白い角丸カード）の延長で、トークン整理と余白調整だけ行う**
  - 工数は最小だが、「どのAI生成ダッシュボードとも区別が付かない」という指摘に応えない。
    （ここでの「トークン」は配色や余白を1か所で決める CSS カスタムプロパティ。`docs/styles.css` 冒頭の `--ink` や `--ai` など）
- **外部フォント（Google Fonts）で書体を指定する**
  - 意図した字形になるが、**オフライン（PWA）で落ちる**。`sw.js` のキャッシュ対象を増やす必要もあり、
    「サーバ運用もビルドも持たない」という前提と合わない。
- **解説の折り畳み（自分の回答と正解だけ開く）を既定にする**
  - スクロールは短くなるが、`docs/js/explain.js` の方針（誤答選択肢が何なのかを読ませる）と、
    それを守る機械検査（`tools/test_past.mjs` の「4選択肢すべてに解説が出る」）に反する。
    ここでの**機械検査**とは、Playwright で実際の画面を操作して結果を数える自動テスト（`npm test`）を指す。
    スクロールの長さは **sticky な `次へ`** で解いた。

## 経緯・根拠

改修前の画面を撮って見たところ、灰背景＋白い角丸18pxカード＋ほぼ黒のアクセントで、
**試験勉強の道具である手掛かりが画面上に一つも無かった**。問題文とUIラベルが同じ書体・同じ太さで、
どこが試験問題かも判別できない状態だった。

明朝を既定にしたのは、初回に「試験の紙」という手掛かりを伝えるため。
⚠️ 画面で読みにくい可能性は実在するリスクだったので、切り替えを1タップで届く場所（設定）に置き、
文字サイズも3段から選べるようにして吸収した。**実機で読みやすさを確認済み（2026-08-20、問題なし）。**

⚠️ 🔥 **この確認がどの端末で行われたかは未記録。** 明朝のフォントスタックは
`'Hiragino Mincho ProN'`（Apple）→ `'Yu Mincho'`（Windows）→ `'Noto Serif JP'` の順で、
**Android には明朝が同梱されない**（`Noto Serif JP` が無ければ既定の serif になる）。
確認済みと読めるのは、確認した端末の系統に限る。

設定の保存先を履歴（`itss-l5-study-state-v*`）と分けたのは、
「同期で他端末の記録から履歴を作り直したときに設定が消える」
「設定の保存で履歴が消える」の両方を防ぐため。
初期適用は `index.html` の `<head>` のインラインスクリプトで行う（描画前に当てないと、
夜テーマで既定の明るい配色が一瞬映る）。

## 覆る条件

- スマホの実機で長時間読んだときに明朝が疲れると判明したら、**既定をゴシックへ変える**
  （`docs/js/settings.js` の `DEFS.examFont.def` が既定値）。方向自体は変えなくてよい。
- **Android 端末で読む運用が始まったとき**は、明朝が出るかを実機で確かめる（出ない場合の既定は要検討）。
- 配色の選択肢が5つを超えたら、トークンの二重管理が重くなるので、テーマ定義を別ファイルへ分離する。

## 副次的な決定（同期カードの移動・空状態の文言・見た目の検査）

- 未設定＝無効のクラウド同期カードを、ホーム最上部から「設定」へ降ろした。
  毎日使う出題より上に、使えない機能とその設定ヒントが居る状態を解消した。
- 空状態（未回答・記録なし）に案内文を入れた。ゼロが並ぶだけの画面は、
  「まだやっていない」のか「壊れている」のか区別できない。
- 見た目と操作の機械検査を `tools/test_ui.mjs` として `npm test` に載せた。
  ⚠️ 色そのものの良し悪しは機械では判定できない。撮影して目で見る
  → [workflow-30-app_画面撮影と自動テスト](../50_workflow/30-app_画面撮影と自動テスト.md)。
