# ADR-0001 ディレクトリ構造と GitHub Pages 配信方式

- 日付: 2026-08-19
- 状態: 採用
- 前提: [memo-0001-10-overview_M2引き継ぎ申し送り](../10_memo/0001-10-overview_M2引き継ぎ申し送り.md)

## 結論

- 配信物一式を **`docs/` へ集約**し、GitHub Pages の**ブランチ配信 `/docs`** で公開する。公開URLは変わらない。
- 公開元ブランチを `agent/m2-supabase-sync` から **`main`** へ一本化する。
- 文書は `10_memo`〜`90_ref`、生成スクリプトは `tools/`、基盤定義は `infra/` に分ける。

## 却下した選択肢

- **配信物をルートに残し、文書だけ番号ディレクトリへ**
  - 変更リスクは最小だが、ルートに配信物8ファイルが残り「ばらばらで管理しにくい」という当初の問題が解決しない。
- **`app/` 等の任意名 + GitHub Actions で Pages デプロイ**
  - ディレクトリ名の意味は正しくなる（`docs/` が文書でないという紛らわしさが消える）が、
    ワークフローという壊れうる可動部が増える。**ビルドもCIも持たない**という本プロジェクトの前提と合わない。

## 経緯・根拠

GitHub Pages のブランチ配信で選べるフォルダは `/` か `/docs` のみ。
任意名にするには Actions 配信が必要で、そこが唯一のトレードオフだった。

`docs/` が「文書」を意味しないという命名の紛らわしさは実在するコストだが、
文書側を番号ディレクトリで明示的に受けているため衝突は起きない。
CLAUDE.md の構造セクションに ⚠️ 付きで定義を明記して吸収する。

配信物の参照はすべて相対パスで自己完結していたため、移動に伴う修正は
`index.html` のスクリプト参照、`app.js` の `fetch` パス、`sw.js` の資産リストの3箇所で済んだ。

## 覆る条件

- 問題数が数千規模になり、JSON分割・検索インデックス生成などの**ビルド工程が必要になったとき**。
  その時点で Actions 配信へ移行し、ディレクトリ名も `app/` 等へ改名してよい。

## 副次的な決定

  改行は LF 固定。移行前後で生成物のハッシュが一致することを確認済み（`aa5de925...`）。
- `.serena/` を `.gitignore` へ追加した。
