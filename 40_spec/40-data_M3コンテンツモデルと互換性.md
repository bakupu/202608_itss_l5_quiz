# M3 コンテンツモデル・互換性仕様

## 目的
M3では「問題」と「用語知識」を分離し、問題追加・解説改善を履歴破壊なしで継続できる構造にする。

## 永続ID
- `concept_id`: 概念の永久ID。例 `security.oauth2`
- `question.id`: 問題の永久ID。例 `security.oauth2.term_to_meaning.001`
- 問題文や解説だけを改善する場合は `question.id` を変更せず `revision` を上げる。
- 問題の意味・正解条件が変わる場合は新しい `question.id` を採番する。
- 廃止問題は削除せず `is_active:false` とし、既存履歴との参照整合性を維持する。

## M2からの履歴移行
`legacy-id-map.json` で旧連番ID 81件を新IDへ対応付ける。
初回起動時に `itss-l5-study-state-v2` / `v1` を読み込み、progressのキーとattempts.question_idを自動変換し、v3へ保存する。
旧データは削除しないためロールバック可能。

## データ分離
- `concepts.json`: 用語辞書。略語、正式名称、日本語、意味、試験ポイント、関連語。
- `questions-v3.json`: 設問、選択肢、正解、選択肢が指すconcept_id、設問固有の理由。
- `legacy-id-map.json`: 旧問題IDから永久IDへの移行表。

同じ用語の説明を複数問題へコピーせず、辞書を一度改善すれば全設問の解説に反映される。

## 解説UI
回答後は正誤にかかわらず4選択肢を同じ密度で表示する。
各概念について以下を表示する。
1. 用語・略語
2. 英語正式名称
3. 日本語
4. 意味
5. 試験ポイント
6. この設問で適切/不適切な理由
7. 関連語

## コンテンツ出典方針
現時点の81問は `source_type: ORIGINAL`。
M3はまずデータモデルと解説品質を改善する段階で、IPA過去問本文の複製は行わない。
今後はIPA公開資料・シラバス・過去問の出題論点を調査し、概念の採用根拠を持たせたオリジナル設問を追加する。
将来的には `source_refs` に出典メタデータを持たせる。

## 拡張目安
- 数百〜1,200問程度: 現構成（GitHub Pages + JSON + localStorage）で運用可能。
- 数千問規模: JSON分割、検索インデックス、IndexedDBを検討。
