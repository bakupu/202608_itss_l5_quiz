## 現状の観察（撮影画像から）

見た目:

- Inter + `#f3f4f6` の灰背景 + 白い角丸18pxカード + ほぼ黒のアクセント。
  **どのAI生成ダッシュボードとも区別が付かない**。試験勉強の道具である手掛かりが画面上に無い
- 問題文とUIラベルが同じ書体・同じ太さで、**どこが試験問題でどこがアプリの声か**が判別できない
- ダーク配色が無い（`theme-color` だけ暗く、実際の画面は明るい）。夜にスマホで開く用途と合っていない

使用感:

- ホームの上から2番目が「クラウド同期」。**未設定＝無効の機能とその設定ヒント**が、
  毎日使う「みっちりやる」より上に居る
- 解説画面が縦5,300px（スマホ幅）。主題カード（その設問が問うている用語の意味・試験ポイントを出す枠）
  ＋4選択肢の解説が全部開いており、
  **`次へ` は最下部**。1問ごとに長距離スクロールを強いる
- 判定が「不正解」の赤い文字のみ。正誤が身体に残らない
- 選択肢の記号が `A. B. C. D.`。IPA本番は `ア イ ウ エ` で、
  出典表記（「令和6年度 秋期 プロジェクトマネージャ試験 午前II 問25」のように問番号を出す）とも噛み合っていない
- PCでキーボードから答えられない（1〜4 / ア〜エ のキー割り当てが無い）
- 初回起動時の数字が「習得0 / 連続0 / 要復習0」の**ゼロ3つ**。空状態の案内が無い
- ダッシュボードの日別バーは0日が線になり、領域別バーは空の灰色。**まだ何も無い**ことしか伝わらない

## 視覚方向の候補

### A. 答案と朱入れ（採用）

題材の世界＝IPAの試験問題そのものから引く。問題文は本番PDFと同じ**明朝**、
アプリの声（ラベル・ボタン・ナビ）は**ゴシック**。この使い分けが
「ここは試験問題／ここはアプリ」の判別をそのまま担う。正誤は朱書きの ○ / × で示す。

- 色: 藍墨 `#17203A`（文字・インク）/ 藍 `#2E5AA8`（主要操作）/ 朱 `#C0392B`（誤答・採点マーク）/
  青緑 `#1C6E52`（正解）/ 上質紙 `#EDF0EC`（背景。冷たい灰緑で、よくある生成りクリームを避ける）/
  罫 `#D3D8D2`
- 書体: すべて**OSの同梱書体**で組む（Google Fonts を使わない）。
  明朝 = `'Hiragino Mincho ProN','Yu Mincho','Noto Serif JP',serif` /
  ゴシック = `'Hiragino Kaku Gothic ProN','Yu Gothic UI','Noto Sans JP',sans-serif`。
  ⚠️ 外部フォントはオフライン（PWA）で落ちるため、`sw.js` のキャッシュ対象を増やしたくない方針と合わない
- 角丸は 18px → 8px、影は捨てて 1px の罫で仕切る（紙の面）
- 署名要素: **五角の到達印**（後述）
- 危うい点: 朱＋紙の取り合わせは、やり過ぎると「和風テンプレ」に落ちる。
  朱は採点マークと誤答だけに使い、面積を持たせない

### B. 夜の計器盤（却下 → 配色の選択肢「夜」として取り込んだ）

暗い背景に1色のアクセント。夜の学習に強く、データが締まって見える。
⚠️ ただし「黒背景＋蛍光1色」は今もっとも生成物っぽい配色で、題材とのつながりも無い。

### C. 現状の延長（却下）

トークン整理と余白調整だけ行い、印象は変えない。工数は最小だが、依頼の「UI印象」には応えない。

## ✅ ゲーミフィケーションの候補

入れる（すべて**既存の状態から導ける**もので、新しい報酬通貨を作らない）:

- [x] **五角の到達印**: 5領域の到達度で満ちる五角形（レーダー）。5領域という試験制度の構造そのものが形になる
  - ⚠️ 検討時は「習得率（Lv4到達数）で満ちる」と書いていたが、**実装では平均習得Lv÷4に変えた**
    （Lv4は7日空けた正解が要るため初週は必ず0%で、毎日の手応えを映せない）。決定は
    [adr-0003](../20_adr/0003-30-app_ゲーミフィケーションと演出の範囲.md)
- [x] **7日ドット**: 直近7日の回答有無。`連続 0 日` という数字より、空きマスの方が「今日やる」に効く
- [x] **習得Lvの階段**: `mastery_level` 0〜4 を5段で表示し、上がった段だけを点灯させる。
      解答直後に「Lv2 → Lv3」を出す（数字の羅列を出している現状の置き換え）
- [x] **朱の判定**: 正誤が出た瞬間に ○ / × を一筆で描く（SVG、約350ms、`prefers-reduced-motion` を尊重）
- [x] 🚫 **試験日カウントダウン** — 中止: 受験区分と日付が未定。後から足せる（ホーム最上段に1行入れるだけ）

入れない:

- ポイント・コイン・ランク・連続日数のボーナス倍率。単独利用の学習履歴に外付け通貨を足しても、
  次の1問を選ぶ判断は何も変わらず、指標が増えるだけ保守が要る
- 紙吹雪の連発。1問ごとに祝うと、正解の意味が薄れる

## ✅ 使用感の修正（視覚方向とは独立に効く）

- [x] 解説の `次へ` を画面下に固定する（長い解説でも1タップで進める）
- [x] 選択肢ごとの解説の開きかたを**設定にした**。既定は4つとも開く
  - ⚠️ 当初は「自分の回答と正解だけ開く」を既定にしようとしたが、
    `explain.js` の方針（誤答選択肢が何なのかを読ませる）と、それを守る機械検査
    （`test_past.mjs` の「4選択肢すべてに解説が出る」）に反する。
    畳むのはスクロールを短くしたい人の選択肢に留め、既定は変えないことにした
- [x] 選択肢の記号を `ア イ ウ エ` に変える（本番と同じ記号で答える練習になる）
- [x] キーボード操作: `1`〜`4` で選択、`Enter` / `Space` / `→` で次へ
- [x] クラウド同期カードをホーム最上部から「設定」へ降ろす
- [x] 空状態の文言を入れる（ホーム・この7日・分析・復習リスト）
- [x] タップ時の押し込み（`:active`）とフォーカスリングを付ける

## ✅ 実装結果（2026-08-20）

3ステップに分けて計画したが、トークンの入れ替えとHTML構造の変更が不可分だったため一度に入れた。

- 追加: `docs/js/settings.js`（見た目の設定。保存先は `itss-l5-ui-v1`。履歴のキーには触らない）
- 追加: `tools/test_ui.mjs`（記号・キー操作・設定の保存とリロード後の復元・空状態）→ `npm test` に載せた
- 変更: `styles.css` 全面（配色4種＝答案・やわらか・夜・端末に合わせる のトークン
  ＝色や余白を1か所で決める CSS カスタムプロパティ、明朝/ゴシックの切り替え、朱の採点マーク、
  Lvの階段、sticky な `次へ`）／`index.html`（ホームの再構成と設定パネル）／
  `app.js`（到達印・7日ドット・記号・キー操作・空状態）／`explain.js`（記号と折り畳み）／
  `text.js`（`CHOICE_MARKS`）／`sw.js`（`CACHE` を `itss-l5-v7` へ、`settings.js` を追加）
- 撮影: `60_shots/before` と `60_shots/after`。夜テーマと設定パネルも撮るよう `tools/shoot.mjs` を拡張
- 検査: `npm test`（履歴移行・辞書・過去問・見た目と操作の4本）が全件成功。
  ⚠️ 件数は増えるので書かない。**実行して確かめる**

### 実装中に判断を変えたところ

- **明朝を既定にした**。画面で読みにくい可能性は残るが、切り替えが1タップで届く場所にあり、
  文字サイズも3段階から選べる。既定をゴシックにすると「試験の紙」という手掛かりが初回に伝わらない
- **到達印は平均習得Lv÷4**にした。ダッシュボードの習得率（Lv4到達数）は7日空けた正解が要るため
  何日も0%のままで、毎日の手応えを映せない。名前も「到達度」と分けてある
- **0%のときは面を描かない**。中心に潰れた多角形は「汚れ」に見え、0%とも故障とも読めた（撮影で発覚）

## ✅ 実機レビューで直した3点（習得率の見え方・陰影と演出・採点印）

実機で確認したところ2点指摘された。どちらも入れ済み。
なお**明朝の読みやすさは問題なし**と判定された（既定を変える必要はない）。

### 1. 「領域別 習得率」が6問全問正解でも0%のまま

**バグではなく仕様どおり**。`masteryAfterAt()` の Lv は
Lv1=答えた / Lv2=正解 / Lv3=**別の日に2連続正解** / Lv4=**Lv3以上を7日以上空けて正解**。
初回セッションでは `correct_streak` が 0→1 にしかならないため必ず Lv2 で止まり、
Lv4（＝「習得」）は最短でも8日目からしか増えない。

🔥 **正しい定義でも、画面上は「毎日やっても動かない棒」＝故障と区別できない。**
判定ロジックは間隔反復の核なので触らず、**見せ方だけ**を変えた。

- 領域別を **Lv1〜4の積み上げ**にし、見出しを「領域別 到達状況」へ（初日から動く）
- KPIの表記を「習得（Lv4）」にし、その下に条件を1行で書いた（なぜ0なのかが画面で分かる）
- 検査（`tools/test_ui.mjs`）: 「回答した当日から領域別の内訳が動く」を機械で見る。
  ⚠️ ここを Lv4 だけの棒へ戻すと落ちる

### 2. フラットすぎて、感情へ働きかける瞬間が無い

- 影を**2層**にした（接地1px + 浮き）。フラットに見えた原因は2層目の不在。夜テーマは縁の明度差で厚みを出す
- 面の上端に1pxのハイライト（`--hi`）を入れた（紙の厚み）
- ホバーで押せる面が浮く（`translateY(-1px)` + 影の拡張）、押下で沈む（`scale(.985)`、影を消す）
- 回答した瞬間、選択肢の色が**下から順に**付く（60msずつ。4つ同時だとどこを見ればいいか分からない）
- **正答**は面の縁が一度だけ青緑に発光。**誤答**は小さく2回だけ横に振れる
  （強く揺らすと読んでいる問題文が読めない）
- 結果画面の正答数・正答率を**数え上げ**る。⚠️ 必ず最終値で終える実装にした
- ホームへ戻ると**五角の到達印がセッション前の広さから広がる**
- すべて `prefers-reduced-motion` で無効化。**情報は演出に載せていない**（消しても読める）

### 3. 正答の演出が「気づかないレベル」だった（2回目のレビュー）

縁の発光と選択肢の色付けは、視線が解説へ移っているため気づかれなかった。
**画面中央に採点印を押す**方式へ変えた。

- 青緑の輪の中に「正解」。0.55倍から現れて1.06倍で止まり、そのまま1.7倍へ広がりながら消える（0.85秒）
- **誤答には出さない**。1問ごとに叱られる画面になるため、誤答は朱の × と小さな振れのまま
- `pointer-events: none` で操作を覆わない。終わったらDOMから消す
- ⚠️ 情報はここに載せていない（消えても `#judge` の「正解」で結果は分かる）
- 検査（`tools/test_ui.mjs`）: 設問データから正解の位置を引いて**必ず正解を押し**、
  印が出る・「正解」と読める・操作を邪魔しない・演出後に消える の4点を見る。
  ⚠️ 「1」を押すだけでは問題によって正誤が変わるため、突き合わせが必要
